# SECURITY-IMPACT

العمليات الحساسة وآليات الحماية والصلاحيات المرتبطة بها. (الجدول مولَّد من السجل: 55 إجراء بخطورة عالية/حرجة من أصل 164 إجراء كتابة.)

## الحماية الموحَّدة لكل إجراء (مفروضة في الخادم)

| الطبقة | ما تفعله |
|---|---|
| المصادقة | جلسة HttpOnly/SameSite=Strict (+Secure و`__Host-` في الإنتاج)، رمز عشوائي 256 بت يُخزَّن بصمته فقط، تدوير عند الدخول، خمول وعمر أقصى قابلان للضبط |
| CSRF | ترويسة `x-csrf-token` مطابقة لرمز الجلسة + فحص Origin |
| الصلاحية | `perms.canRunAction` عند كل طلب: مساحة ← قسم ← زر، والمالك فقط يغيّرها (بإصدار متفائل وتدقيق وتراجع). أي رفض يُسجَّل في التدقيق وتكراره يرفع تنبيهاً |
| المدخلات | Zod صارم (`strict`) — حقول مجهولة مرفوضة؛ حدود وأنماط ومعرّفات Discord/Firestore تُتحقق |
| التأكيد | الخطورة ≥ متوسطة تتطلب `confirm:true` **في الخادم** (لا تكفي الواجهة)؛ الحساسة تتطلب **سبباً** (≥3 أحرف) |
| عدم التكرار | مفتاح لكل عملية: إعادة الطلب تعيد النتيجة نفسها، وتعارض المدخلات مرفوض، والمتزامن يُرفض 409؛ الفشل لا يحجز المفتاح |
| القدرة | الخدمة غير المُهيّأة ← 503 بسببها (لا كتابة ولا نجاح) |
| التحقق | `verify` يعيد قراءة المصدر الأصلي؛ عدم التطابق ← فشل `VERIFY_FAILED` |
| التدقيق | سجل إضافة فقط بسلسلة تجزئة (يُكشف أي تلاعب)، قبل/بعد، سبب، طلب، IP مقنّع؛ الأسرار والبريد تُحجب |
| التراجع | الإجراءات القابلة للعكس تسجّل عكسها؛ يُنفَّذ عبر نفس المحرك والصلاحيات مرة واحدة فقط |
| اللاعب/العضو المحمي | لا عقوبات على مالك السيرفر ولا على البوت؛ الجماعي يتطلب معاينة وتطابق العدد |

## الأسرار

- لا يصل المتصفح أي سر: Service Account، توكن البوت، `x-api-key`، روابط قواعد البيانات تبقى في الخادم. `GET /api/capabilities` يعيد «مُهيّأ/غير مُهيّأ» وسبباً فقط.
- كلمات المرور: Argon2id (19MiB, t=2) من متغير بيئة؛ لا تُسجَّل ولا تُخزَّن بنص صريح (`OWNER_PASSWORD` يُتجاهل في الإنتاج).
- سجلات الخادم تمرّ عبر `scrub` (يحجب token/secret/password/api-key/cookie…).
