# SECURITY-AUDIT

فحص أمني ذاتي للوحة (الكود + الاختبارات الآلية). **ليس اختراقاً خارجياً مستقلاً.** كل بند «مُثبَت باختبار» له اختبار فعلي في `test/`.

## 1) الأسرار والاعتماديات

| الفحص | النتيجة |
|---|---|
| مسح المستودع بحثاً عن كلمتي المرور المعطاتين، مفاتيح خاصة، توكنات Discord/Google/Slack | **لا شيء** (الاختبارات تستخدم كلمات مرور اختبار منفصلة تُحقن بالبيئة) |
| كلمات المرور في الكود/الواجهة/السجلات/التدقيق | غير موجودة — مُثبَت باختبار (`auth.test.js`: «كلمات المرور لا تُسجَّل…») |
| `npm audit --omit=dev` (ما يُنشر) | **0 ثغرة** (رُقّيت `zod` إلى 4.x لإصلاح GHSA-mrhx-c7xc-m3w5) |
| `npm audit` كاملاً | ثغرات في اعتماديات **تطوير فقط** من `firebase-tools` (محاكيات الاختبار): `tar`, `basic-ftp`, `csv-parse`… — لا تُنشر (`npm ci --omit=dev`) ولا تعمل في الإنتاج |
| الأسرار في المتصفح | لا Service Account/توكن/مفتاح API/رابط قاعدة يصل المتصفح؛ `/api/capabilities` يعيد «مُهيّأ/غير مُهيّأ» فقط |
| تشفير كلمات المرور | Argon2id (19MiB, t=2, p=1)؛ مقارنة بزمن ثابت؛ تجزئة وهمية لحساب غير معروف (يساوي الزمن) |

## 2) المصادقة والجلسات (مُثبَت باختبار)

- حسابان ثابتان؛ لا مسارات تسجيل/استعادة (404/401).
- رد موحّد لكلمة مرور خاطئة وحساب غير موجود (منع التعداد).
- قفل تصاعدي لكل (حساب + IP) بعد 3 إخفاقات؛ **فشل مهاجم من عنوانه لا يقفل المالك من عنوان آخر**؛ قفل عام للحساب فقط عند 25 فشلاً متتالياً موزَّعاً؛ حد 20 محاولة/15د لكل IP؛ حظر IP يدوي.
- كوكي HttpOnly + SameSite=Strict (+`__Host-` و`Secure` في الإنتاج)؛ الرمز 256 بت، المخزَّن بصمته فقط؛ تدوير عند الدخول؛ خمول (30د) وعمر أقصى (12س) قابلان للضبط؛ انتهاء الجلسة يُبطلها.
- رمز عشوائي/معدَّل ← 401؛ إرسال `role/account` في الجسم لا يغيّر الهوية.
- CSRF: ترويسة الرمز + فحص Origin (Origin غريب ← 403).

## 3) الصلاحيات

- تُفرض في الخادم عند **كل** طلب إجراء/عرض/بحث (`canRunAction`/`canSeeSection`)؛ اختبار يمرّ على **كل الـ214 إجراءً** كأدمن مقيَّد ويتحقق من 403 حتى لو أُرسل الطلب يدوياً.
- مسارات المالك (`/api/access/matrix` وأقسام الصلاحيات/الأمان الحساسة) ← 403/404 للأدمن.
- تغيير المالك للصلاحيات يسري فوراً (قراءة مباشرة من المخزن) ويُدقَّق ويُسقَط التعارض بإصدار.
- الإجراءات المرفوضة تُسجَّل، وتكرارها (≥5/10د) يرفع تنبيه «طلبات مشبوهة» واحداً.

## 4) فئات الحقن والهجمات

| الفئة | الحماية |
|---|---|
| SQL Injection | كل استعلامات SQLite/Postgres بمعاملات؛ أسماء الجداول/الحقول ثوابت أو قائمة بيضاء (`FIELD` regex)؛ لا SQL من المتصفح (اختبار: `botdb/run_sql` ← 404) |
| NoSQL / مسارات Firestore-RTDB | معرّفات المستندات تُتحقق (`isDocId`)؛ المسارات مبنية من قوالب ثابتة + معرّف متحقَّق؛ مفاتيح الأكواد تُطبَّع كالموقع (إزالة `. # $ [ ] /`) |
| XSS | الواجهة تهرب كل نص (`esc`)؛ CSP `script-src 'self'` + `style-src 'self'` (لا سكربت/نمط مضمّن — مُثبَت باختبار)؛ `frame-ancestors 'none'` |
| CSV/Formula Injection | حقول تبدأ بـ`= + - @` تُسبَق بـ`'` في كل تصدير (اختبار) |
| Path Traversal | اسم ملف النسخة الاحتياطية يطابق `^[A-Za-z0-9._-]+\.sqlite$` (اختبار: `../../etc/passwd` ← 422) |
| SSRF | لا جلب لروابط يدخلها المستخدم؛ الوجهات من الإعدادات فقط |
| Brute-force/DoS | حدود دخول؛ جسم الطلب ≤200KB؛ حدود الأطوال في Zod؛ مهلة 10ث لـDiscord، 6ث للفحوصات |
| Replay | مفاتيح عدم التكرار؛ الجلسة المنتهية ترفض كل شيء |
| التلاعب بالتدقيق | لا مسار تعديل/حذف؛ سلسلة تجزئة تكشف التلاعب المباشر بالقاعدة (اختبار) |
| تسرّب PII | البريد مقنّع (`ah***@…`) في التصدير والتدقيق؛ IP مقنّع (/24)؛ `before` لا يحمل مستند اللاعب |

## 5) المخاطر المتبقية والتوصيات (بصراحة)

1. **كلمتا المرور أُرسلتا في محادثة نصية** — اعتبرهما مكشوفتين: **غيّرهما** وولّد مشتقات جديدة بـ`npm run hash-password`. كلمة مرور الأدمن (`lhq…`، 8 أحرف حروف+أرقام) **ضعيفة**؛ الحماية الحالية (قفل/حد) تبطئ التخمين لكنها لا تعوّض كلمة قوية — يُنصح بـ14+ حرفاً.
2. اللوحة تملك **Admin SDK للموقع وتوكن البوت** (تتجاوز قواعد Firestore بطبيعتها). اختراق خادمها = اختراق كل شيء. انشرها على نطاق فرعي منفصل، وفضّل طبقة إضافية (Cloudflare Access/VPN/قائمة IP) وبيئة أسرار محمية، وأعطِ حساب الخدمة أقل الأدوار الممكنة.
3. قفل (حساب+IP) خلف Proxy يعتمد صحة `X-Forwarded-For` (`TRUST_PROXY=true` فقط خلف وكيل موثوق).
4. قاعدة اللوحة ملف SQLite واحد: **اربطها بقرص دائم** وخذ نسخاً دورية؛ لا تعدد نسخ للخدمة (الجدولة/الأقفال تفترض عملية واحدة).
5. لا 2FA. التوصية: TOTP للمالك.
6. إعادة تفعيل حساب Firebase المحظور مؤقتاً يعتمد عمل مجدول اللوحة؛ فشله يرفع تنبيهاً ولا يختفي صامتاً. رمز ID الحالي للاعب المحظور قد يبقى صالحاً حتى ساعة (سلوك Firebase) رغم سحب الجلسات.
7. حالات `apply=restart/ttl` للبوت: المسؤول يرى أنها «معلّقة» — لا تُعامَل كنافذة فورياً.
8. هذا الفحص لم يتضمن اختبار اختراق من طرف ثالث ولا تحليلاً لسلسلة توريد `firebase-tools` (تطوير فقط).
