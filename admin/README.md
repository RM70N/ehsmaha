# ادمن احسمها — لوحة التحكم الإدارية

لوحة تحكم منفصلة تماماً عن ehsmaha.com، مرتبطة بنفس مشروع Firebase (نفس
`streamgame-180b8`) — قراءة وكتابة فعلية على نفس قاعدة البيانات، بدون أي
بيانات وهمية. مخصصة لحساب واحد فقط (`malshaifan1@gmail.com`).

## الحالة الحالية

**كل الأقسام الـ60 مبنية وموصولة فعلياً** (كل واحد فيه أدوات حقيقية على
بيانات حقيقية بنفس مشروع Firebase؛ أي أداة تحتاج مفتاح/خدمة خارجية أو
بيانات غير مسجَّلة أصلاً بالموقع الرئيسي معلَّمة بوضوح بشارة "يحتاج ربط
خارجي" أو "بيانات غير متوفرة بعد" بدل التظاهر بأنها تعمل):

- **1-30**: نظرة عامة، اللاعبين، الستريمرز، الإطارات، الشارات، إحصائيات
  الألعاب، الجلسات المباشرة، الاقتصاد الداخلي (XP)، التذاكر، الرسائل
  والإشعارات، الأمان، مراقبة المحتوى، اصنع لعبتك، الفائزين والمسابقات،
  السيو، سجل الأحداث، API منصات البث، تحليلات النمو، الفعاليات الخاصة،
  أوفرلاي الستريمرز، بنوك الأسئلة، التقارير المالية، الأجهزة والجلسات،
  الأداء التقني، النسخ الاحتياطي، صلاحيات المشرفين، اختبار A/B، اللغة
  والترجمة، الصيانة، إعدادات اللوحة.
- **31-41**: لوحة تحكم مخصَّصة لكل لعبة "رئيسية" على حدة — شد الحبل، الضوء
  الأخضر/الأحمر، سرقة التاج، جسر المصير (فعالية Realtime Database حية —
  حالة/مشاركين/طرد/إنهاء طارئ حقيقي)، القنبلة المتحركة، حرب الدول، دائرة
  الإقصاء، الكرسي المتحرك، الأراضي البركانية، الطريق الزجاجي، توب 10.
- **42-44**: لوحات فئة مجمَّعة (بدل تكرار نفس الأدوات لكل لعبة صغيرة) —
  7 ألعاب أونلاين، 18 لعبة "جمعات"، 11 لعبة فردية — إحصائيات، جلسات حية،
  تفعيل/تعطيل جماعي، أخطاء تقنية، تصدير.
- **45-60**: شاشات مشتركة (إعداد/انتظار/راوند/إقصاء/فوز)، ربط حسابات
  الستريمر (bridgeStreamers)، بروفايل اللاعب، ربط تيك توك للاعبين، القائمة
  الجانبية للوحة نفسها، لوحة الفائزين العامة (leaderboards)، صفحات السيو
  المنشورة، هوية العلامة، قنوات متعددة، أكواد دخول الغرف (rooms).

### تصحيحان بالتسمية عن خطة العمل الأولى

قسمان من 31-44 كانا مكرَّرين حرفياً بخطة العمل الأولى قبل المراجعة
الدقيقة لكود الموقع الرئيسي، فاستُبدلا بلعبتين حقيقيتين منفصلتين بدل بناء
نفس المحتوى برقم قسم آخر:
- **قسم 33** كان "لعبة نجاة من اللافا" — تبيّن إنها نفس لعبة "الأراضي
  البركانية" (قسم 39) حرفياً بوصف مختلف، لا لعبة منفصلة. استُبدل بـ"سرقة
  التاج" (tag: `cs`).
- **قسم 35** كان "لعبة مصيرك" — تبيّن إنها مجرد جملة نص داخل واجهة "جسر
  المصير" (قسم 34)، لا لعبة منفصلة. استُبدل بـ"القنبلة المتحركة"
  (tag: `bomb`).

كذلك 3 أقسام من 45-60 كانت تكراراً مفهومياً لأقسام موجودة (51 ≈ 20، 56 ≈
13، جزء من 57 ≈ 15) — بدل تكرار نفس الأدوات، صارت مراجع مختصرة تنقلك
للقسم الأصلي، مع إبقاء أي زاوية حقيقية غير مغطاة (مثل سجل النشر بقسم 57).

### تصحيح مهم على "جسر المصير" (bridgeEvents)

جسر المصير لا يستخدم Firestore إطلاقاً لبيانات الفعالية الحية — يستخدم
Realtime Database (المسارات `bridgeEvents/{id}`، `bridgePlayers/{eventId}/{key}`،
`bridgeBoard/{eventId}`) تفادياً لحصة قراءات/كتابات Firestore. كان
`firestore.rules` فيه قسم قواعد Firestore وهمي بنفس الاسم من افتراض خاطئ
بمرحلة سابقة — أُزيل لأنه ميت فعلياً. **أمان جسر المصير الحقيقي يُدار من
Firebase Console → Realtime Database → Rules، خارج `firestore.rules`
تماماً** — تأكد إن تلك القواعد تسمح بالقراءة للجميع والكتابة للمستخدمين
المسجَّلين دخول فقط (نفس فكرة `isOwner()` بصياغة RTDB:
`auth.token.email === 'malshaifan1@gmail.com'`).

## كيف تنشرها كموقع Netlify منفصل

1. من لوحة Netlify: **Add new site → Import an existing project** واختر
   نفس ريبو GitHub (`RM70N/ehsmaha`).
2. **Base directory**: `admin`
3. **Publish directory**: `admin` (أو `.` إذا حدّدت Base directory أعلاه —
   Netlify يقرأ `admin/netlify.toml` تلقائياً بهالحالة).
4. **Build command**: اتركه فاضي (موقع ثابت بدون بناء).
5. بعد أول نشر، من إعدادات الموقع بـNetlify أضف نطاق فرعي مخصص مثل
   `admin.ehsmaha.com` (Domain settings → Add custom domain) ووجّه DNS له.
6. **مهم بإعدادات Firebase**: Authentication → Settings → Authorized domains
   — أضف نطاق موقع Netlify الجديد (و/أو `admin.ehsmaha.com`) حتى يقدر
   تسجيل الدخول يشتغل من عليه.

## تسجيل الدخول

نفس حساب Firebase Auth الموجود أصلاً (البريد وكلمة المرور اللي تستخدمها
بحساب `malshaifan1@gmail.com` على ehsmaha.com نفسه) — لأنه بنفس مشروع
Firebase تماماً. أي حساب ثاني ينجح بتسجيل الدخول (حساب حقيقي بس مو
المصرَّح له) يُرفض تلقائياً ويُسجَّل بالقسم 16/11.

## قواعد Firestore

أضفنا قواعد جديدة بـ`firestore.rules` بجذر الريبو (نفس الملف اللي يخدم
الموقع الرئيسي) لكل الكولكشنات الجديدة اللي تحتاجها اللوحة. لازم تُنشر
هذي القواعد على Firebase (من Firebase Console → Firestore → Rules، الصق
محتوى الملف كامل ثم Publish — أو عبر Firebase CLI: `firebase deploy
--only firestore:rules` لو عندك المشروع مربوط محلياً).

## أدوات تحتاج ربط خارجي (حسب قرارك: أكمل الممكن ببيانات حقيقية وعلّم الباقي)

كل أداة عليها وسم "يحتاج ربط خارجي" أو "بيانات غير متوفرة بعد" (شارة على
بطاقة الأداة نفسها باللوحة، وبنص واضح داخل الأداة عند فتحها) جاهزة
الهيكلة والمنطق بالكامل — فقط ناقصها مفتاح/خدمة خارجية (بريد، Render API،
Firebase Management API، Google Search Console، خدمة ذكاء اصطناعي...)
أو بيانات مصدرها غير مسجَّل أصلاً بالموقع الرئيسي حالياً. القائمة تكبر مع
كل قسم جديد، فبدل تكرارها هنا — أي أداة بهذي الحالة تشرح بوضوح داخل نفسها
وش بالضبط ناقصها لتفعيلها بالكامل. أبرز الأمثلة المتكررة:

- **إرسال بريد/تنبيهات خارجية** (قسم 11.13، 30.12): يحتاج خدمة إرسال بريد
  (مثل EmailJS أو Resend) — الإعداد والحفظ جاهزين، بس الإرسال الفعلي معطّل
  لحد ما تزوّدني بمفتاح الخدمة.
- **مقاييس منصّات خارجية** (قسم 24 حصة Firebase/Render، قسم 15 Google
  Search Console، قسم 17 حدود API المنصات): تحتاج مفاتيح API لتلك الخدمات
  تحديداً.

بالإضافة لهذي، فيه بندان بقسم 1 (نظرة عامة) ما عندهم بيانات مصدرها موجود
بالموقع الرئيسي حالياً (مو مسألة مفتاح API، مسألة بيانات غير مُسجَّلة أصلاً)
— موضَّحين بوضوح داخل اللوحة نفسها بدل رقم وهمي:

- **1.10 — عدد البلاغات غير المراجَعة**: ما فيه نظام بلاغات لاعبين
  بالموقع حالياً؛ راح يشتغل بمجرد بناء قسم 12 (مراقبة المحتوى) بمرحلة قادمة.
- **1.11 — متوسط مدة الجلسة اليوم**: الموقع الرئيسي يسجّل "آخر ظهور" فقط
  بدون وقت بداية/نهاية جلسة — أخبرني إذا تبيني أضيف هذا التسجيل بمرحلة قادمة.

## إضافات صغيرة على الموقع الرئيسي (index.html)

عشان الأقسام 1، 11، و23 تشتغل ببيانات حقيقية 100%، أضفنا 3 إضافات صغيرة
وآمنة (best-effort بالكامل، ما توقف أو تبطئ الموقع الرئيسي أبداً لو فشلت):

1. **تتبع جهاز بسيط** (`deviceSessions`) عند كل تسجيل دخول — بصمة جهاز محلية
   + متصفح/نظام/موقع تقريبي، مع إمكانية تسجيل خروج جهاز معيّن أو حظره عن
   بُعد من قسم 23.
2. **فحوصات أمنية عند التسجيل** (`siteFlags`, `adminIpBans`,
   `signupRateLimit`) — تعطيل تسجيل جديد مؤقتاً، قائمة سوداء لليوزرات، حظر
   IP، وحد معدل طلبات — كلها تُدار من قسم 11.
3. **سجل أخطاء عميل خفيف** (`clientErrorLog`) — يسجّل أخطاء JavaScript
   الحقيقية اللي تصير للاعبين (بحد أقصى كتابة كل 10 ثواني)، يُستخدم بتنبيه
   1.12.
4. **حاجز صيانة حي + توزيع A/B بنسبة مئوية** — إضافتان صغيرتان لقسمي 29
   و27: أول واحدة تفحص `siteFlags/maintenance` لحظياً (`onSnapshot`) وتعرض
   حاجز صيانة كامل الشاشة لكل الزوار عدا حساب المالك؛ الثانية تحسب hash
   ثابت من uid المستخدم عشان يفضل بنفس مجموعة تجربة A/B (A أو B) طول
   الوقت بدل ما تتغيّر عشوائياً كل تحميل صفحة — كلاهما مطبَّقان فعلياً على
   الموقع الرئيسي الآن، لا مجرد واجهة إدارة بدون أثر.

كلها كولكشنات Firestore جديدة تماماً، ما لمسنا أي كولكشن أو منطق موجود.

## اختبار محلي

اتأكدت إن كل ملفات JS/CSS بمجلد `admin/` تحمل بنجاح (200) وتحل كل استيراد
ES Module بينها بشكل صحيح (تشغيل محلي عبر متصفح فعلي بلا أخطاء تحميل ملفات).
الاتصال الفعلي بـFirebase وتسجيل الدخول يحتاج بيئة فيها وصول شبكي حقيقي
لـ`gstatic.com`/`firebaseapp.com` (غير متاح من بيئة التطوير المعزولة هذي) —
جرّبه بنفسك بعد النشر على Netlify.
