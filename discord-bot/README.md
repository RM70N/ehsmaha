بوت ديسكورد رسمي لمنصة **[احسمها](https://ehsmaha.com)** مبني بـ **Node.js + discord.js v14** (أوامر Slash فقط)، مرتبط مباشرة بقاعدة بيانات الموقع الفعلية (**Firebase — مشروع `streamgame-180b8`**) عبر طبقة API مستقلة (Express).

## 🧭 كيف تشتغل المنظومة

```
┌──────────────┐  x-api-key   ┌──────────────────────┐  Admin SDK  ┌──────────────────────────┐
│ بوت ديسكورد  │ ───────────▶ │ طبقة الـAPI (Express) │ ──────────▶ │ Firebase (Firestore/RTDB) │
│  (npm start) │   HTTPS      │  (npm run start:api)  │             │ نفس قاعدة بيانات الموقع    │
└──────┬───────┘              └──────────────────────┘             └──────────────────────────┘
       │ ▲ POST /api/discord/stream-event (x-webhook-secret) ← أحداث البث (اختياري)
       ▼ │ GET /active-streams (مزامنة /بث — لحظية بالـAPI المدمجة)
┌──────────────────────────────┐
│ قاعدة بيانات البوت           │  SQLite + حفظ دائم سحابي تلقائي (أو PostgreSQL اختياري)
│ إدارة · تكتات · تحذيرات · سجل │  الجداول تنشأ تلقائياً
└──────────────────────────────┘
```

- **بدون أي ربط حسابات:** كل أوامر اللاعب تاخذ **اليوزرنيم** مباشرة (`/بروفايل يوزر: ahmed_1`)، والبوت يبحث عنه بقاعدة بيانات الموقع ويعرض بياناته — لك أو لأي لاعب ثاني.
- **البوت** ما يتصل بقاعدة البيانات مباشرة — كل شي عبر الـAPI بمفتاح سري (`x-api-key`)، مع مهلة 5 ثوانٍ وإعادة محاولة وحدة.
- **الـAPI** يقرأ بيانات الموقع الحقيقية (`usernames`، `users`، `levels`، `leaderboards`، `streamerEvents`...) وما يكتب إلا مجموعاته الخاصة (`discordApiStats`، `discordWeeklyBaselines`، والنسخة الدائمة لقاعدة البوت `discordBotState`).

### كيف يشتغل البحث باليوزرنيم
1. تنظيف المدخل: حذف الفراغات الزائدة والرموز المخفية و`@` بالبداية، توحيد الحروف العربية (NFC)، وتحويله لأحرف صغيرة — يعني **البحث case-insensitive**.
2. حساب مسجّل بالموقع: `usernames/{usernameLower}` ← `users/{uid}` (نفس فهرس اليوزرات بالموقع)، واحتياطاً استعلام `users.usernameLower`.
3. لو ما لقى حساب: يدور على **لاعب بث** بدون حساب (متابع تيك توك/كيك/يوتيوب له سجل بـ`levels`) — فتقدر تعرض بيانات أي متابع لعب ببث.
4. ما لقى شي ← رسالة: *"لم يتم العثور على لاعب بهذا الاسم، تأكد من كتابته بشكل صحيح كما هو مسجل بالموقع"*.

اليوزرنيم يُرسل بالرابط مشفّراً (`encodeURIComponent`، UTF-8) فالأسماء العربية والرموز تشتغل بأمان.

**Autocomplete:** أثناء كتابة خيار `يوزر` تطلع حتى 25 اقتراح من الموقع (👤 حساب مسجّل، 🎮 لاعب بث) تبدأ بنفس الحروف. لو الـAPI بطيء أو طايح، القائمة تطلع فاضية بس والأمر نفسه يشتغل عادي.

## ⚙️ التثبيت المحلي

```bash
cd discord-bot
npm install
cp .env.example .env      # ثم عبّي القيم (الجدول تحت)
npm run check             # فحص الأوامر بدون اتصال
```

شغّل الخدمتين (كل وحدة بطرفية):

```bash
npm run start:api         # طبقة الـAPI على http://localhost:3000
npm start                 # البوت
```

> محلياً خل `API_BASE_URL=http://localhost:3000`.

## 🛰️ قناة التحكم الإدارية و PostgreSQL

- **قناة `/admin-control/*`**: واجهة آمنة للوحة الإدارة الخارجية (تعطيل/تقييد الأوامر، إعادة تحميل الخدمات، حدود الحماية، أسباب التكتات، روم إعلانات الستريمرز…). موثّقة بالكامل مع أمثلة curl بـ [`ADMIN-CONTROL-API.md`](./ADMIN-CONTROL-API.md). خاملة حتى تحط `ADMIN_CONTROL_KEY`.
- **PostgreSQL**: حط `DATABASE_URL=postgres://user:pass@host:5432/db` (يُفعَّل SSL تلقائياً للمضيفين البعيدين) وتتطبّق الـmigrations (001–013) تلقائياً عند التشغيل. بدونه يستخدم SQLite المحلي.
- **نقل بيانات SQLite → PostgreSQL** (آمن للتكرار، ما يحذف شي، يطبع عدد الصفوف قبل/بعد):

```bash
DATABASE_URL=postgres://... node scripts/migrate-sqlite-to-postgres.js --sqlite ./data/bot.sqlite   # أضف --dry للتجربة بدون كتابة
```

يدوياً (اختياري): سجّل الأوامر من جديد **كل ما** أضفت/عدّلت اسم أمر أو خياراته. (تعديل منطق التنفيذ فقط ما يحتاج.)
التسجيل يستبدل القائمة كاملة، فأي أمر قديم انحذف من `commands/` ينشال من ديسكورد تلقائياً.

الصلاحيات: View Channels, Send Messages, Embed Links, Read Message History, Use External Emojis, **Manage Messages** (/مسح + حذف الروابط والسبام)، **Manage Channels** (التكتات)، **Manage Roles** (رتب التحذير)، **Timeout Members** (/كتم + الكتم التلقائي)، **Kick Members** (/طرد)، **Attach Files** (بطاقة الترحيب).
البوت يفحصها بكل سيرفر عند الإقلاع، وكل أمر إداري يفحص صلاحياته قبل التنفيذ ويقولك **اسم الصلاحية الناقصة بالضبط**.

> ⚠️ **ترتيب الرتب:** اسحب رتبة البوت (**احسمها**) فوق رتب الأعضاء ورتب التحذير بـ Server Settings → Roles — ديسكورد ما يسمح للبوت يكتم/يطرد/يعطي رتبة لأحد رتبته أعلى من البوت.
>
> **الـIntents (مهم للترحيب والحماية):** discord.com/developers → تطبيق احسمها → **Bot** → Privileged Gateway Intents:

> - ✅ **Message Content Intent** — بدونه ما يقدر يقرأ نص الرسائل (ما فيه كشف روابط ولا تكرار؛ سبام السرعة يشتغل).
>
> البوت يقرأ من ديسكورد وش المفعّل ويشتغل بدون الناقص بدل ما يطيح، ويكتب تحذير واضح بالسجل.

## 🚀 النشر على Render

### الطريقة السريعة (Blueprint)
1. Render Dashboard → **New → Blueprint** → اختر المستودع.
2. **Blueprint Path:** `discord-bot/render.yaml`
3. عبّي القيم السرية اللي يطلبها (`DISCORD_TOKEN`، `API_KEY`، `FIREBASE_SERVICE_ACCOUNT`، `GEMINI_API_KEY`، `ADMIN_IDS`).

**خدمة وحدة:** طبقة الـAPI (Firebase) تشتغل **داخل البوت** على منفذ داخلي — خدمة وحدة شغالة 24/7 (≈720 ساعة بالشهر) تكفيها ساعات Render المجانية (750)، بدل خدمتين يخلصونها قبل آخر الشهر.
> ⚠️ `API_KEY` لازم يبقى **نفس القيمة القديمة** — نسخة إعدادات البوت المحفوظة مشفّرة فيه.

### يدوياً
**خدمة البوت** — New → **Web Service** (يستقبل Webhook البث وربط الألعاب + `/health`)
- Root Directory: `discord-bot`
- Build: `npm ci --omit=dev` — Start: `npm start`
- Health Check Path: `/health`
- المتغيرات: `DISCORD_TOKEN`, `CLIENT_ID`, `API_KEY`, `FIREBASE_SERVICE_ACCOUNT`, `GEMINI_API_KEY`, `ADMIN_IDS`, `STREAM_WEBHOOK_SECRET`, `NODE_ENV=production` — **بدون** `API_BASE_URL`
- (اختياري) خدمة API منفصلة: Start `npm run start:api` بمتغيرات `API_KEY`, `FIREBASE_SERVICE_ACCOUNT` — وحط رابطها بـ`API_BASE_URL` بخدمة البوت.
- ينفع كـ**Background Worker** بعد، بس بدون Webhook (`/بث` بالمزامنة فقط).

> **الخطة المجانية:** الـWeb Service المجانية "تنام" بعد 15 دقيقة بلا طلبات HTTP خارجية —
> الاتصال الدائم بديسكورد **لا يمنع هذا**، فالبوت ينقطع فجأة لين يوصله طلب يصحّيه (تأخير حتى 50 ثانية).
> - الـAPI: البوت يطلبه كل دقيقة (مزامنة `/بث`) فيبقى صاحي تلقائياً — ما يحتاج شي إضافي.
> - البوت: يرسل لنفسه نبضة (`GET /health`) كل 10 دقائق تلقائياً (`RENDER_EXTERNAL_URL` اللي يعبّيه Render نفسه) — يبقى صاحي أغلب الوقت بدون أي إعداد إضافي.
> - **لضمان 24/7 بدون أي انقطاع** (حتى أثناء إعادة نشر Render نفسها، أو لو تجاوزت الخدمتان سقف الساعات المجانية المشترك بالحساب): رقّي خدمة البوت (وخدمة الـAPI لو تحملها) لخطة **Starter** المدفوعة — Settings → Instance Type.

**3) قاعدة بيانات البوت — تلقائية، ما تحتاج أي إعداد**
- البوت يستخدم SQLite، وعلى Render يحفظها **سحابياً بشكل دائم** عبر خدمة الـAPI، بمخزنين:
  - **Realtime Database** (الأساسي، مسار `discordBotState`) — ما لها حد قراءات يومي، فتشتغل حتى لو خلصت حصة Firestore.
  - **Firestore** (احتياطي تلقائي، مجموعة `discordBotState`) — لو Realtime Database ما ردت خلال 10 ثوانٍ.
  - المحتوى **مشفّر** (AES-256-GCM بمفتاح من `API_KEY`)، وعند الاسترجاع يُختار الأحدث من المخزنين.
  - آلية الحفظ:
  يرفع نسخة بعد 3 ثوانٍ من أي تعديل، ويرفع فوراً عند الإيقاف (SIGTERM قبل كل تحديث)، ويسترجعها أول ما يقلع.
- الأوامر الإدارية ما تشتغل لين يكتمل الاسترجاع (رسالة "البوت يجهّز بياناته")، فما تنمسح النسخة المحفوظة بقاعدة فاضية أبداً.
- أثناء التحديث تشتغل نسختين لحظات: الأحدث تستلم النسخة والأقدم يُرفض رفعها تلقائياً.
- تتأكد من حالتها برابط `https://<خدمة-البوت>.onrender.com/health` ← `"backup": { "enabled": true, "restored": true, ... }`.
- (اختياري) PostgreSQL: حط `DATABASE_URL` وبيستخدمه بدل كل ما سبق.

**4) Webhook البث (اختياري)** — بخدمة البوت أضف `STREAM_WEBHOOK_SECRET` (سر عشوائي 32+ حرف). البوت لازم يكون **Web Service** عشان يستقبله. التفاصيل بقسم [📡 Webhook البث](#-webhook-البث--للفريق-التقني-بالموقع).

**5) بعد النشر**
- الأوامر تنسجل تلقائياً أول ما يشتغل البوت (تأكد من سطر "تم تسجيل الأوامر" بالـLogs). العالمية ممكن تاخذ لين ساعة لتظهر.

### التعديلات على الموقع (index.html)
- تسجيل **`bestRoundPoints`** (أعلى نقاط بجولة واحدة) بحساب اللاعب عند فوز الأونلاين — يظهر بـ`/احصائيات`.
- رابط `ehsmaha.com/profile` (زر "فتح الموقع" بالبوت) يفتح صفحة البروفايل بعد تسجيل الدخول.

### 🛡️ الأوامر الإدارية

**مين يقدر يستخدمها؟** دالة وحدة `checkAdminPermission` تتحقق بالترتيب:
1. صلاحية **Administrator** الحقيقية بالسيرفر (أو مالك السيرفر) ← مسموح
2. العضو مضاف بـ`/اضافة_ادمن` ← مسموح

### 🎫 نظام التكتات
1. العضو يضغط **افتح التكت** ← تطلع له قائمة أسباب (من `config/ticketReasons.js` — عدّلها هناك بدون لمس الكود).
2. يختار السبب ← البوت يتأكد ما عنده تكت مفتوح من نفس اللوحة (لو عنده، يعطيه رابطه)، ثم ينشئ روم خاص `دعم-اسمه`:
   - @everyone: ممنوع يشوف · صاحب التكت ورتب الدعم: يشوف/يكتب/يقرأ السجل · البوت: صلاحيات كاملة.
3. رسالة ترحيب بمنشن العضو والسبب وزر **إغلاق التكت** ← تأكيد/إلغاء.
4. الإغلاق: `archive` = نقل لتصنيف "تكتات مغلقة" وقفل الكتابة، أو `delete` = حذف بعد 10 ثوانٍ.
- كل الأزرار بمعرّفات ثابتة محفوظة بقاعدة البيانات ← **تشتغل حتى بعد إعادة تشغيل البوت**، والحذف المعلّق يكمل بعد الإقلاع.
- لو أحد حذف روم التكت يدوياً، التكت يتسكّر تلقائياً ويقدر العضو يفتح جديد.
- **المساعد الذكي** يرد داخل كل تكت، وملخص كل تكت ينقفل يوصل قناة أخبار الأدمن — التفاصيل بقسم "🤖 مساعد احسمها الذكي" تحت.
- **حتى لو ضاعت بيانات التكتات:** زر اللوحة القديم يشتغل (قناة اللوحة = قناة الزر)، وأزرار الإغلاق تتعرف على التكت من الروم نفسه (موضوع الروم فيه صاحبه وسببه)، ومنع التكرار يفحص الرومات المفتوحة.

### 👋 نظام الترحيب البصري

1. **بطاقة ترحيب (صورة)** بتصميم احسمها: أفتار العضو مقصوص دائرياً بالضبط داخل الإطار الذهبي، ويوزره متوسّط بالشريط البنفسجي.

### 🎮 الألعاب
`/العاب` يعرض كل ألعاب ديسكورد المتوفرة (بنفس تصميم `/مساعدة`). القائمة من **`config/games.js`** — أي لعبة تنضاف هناك تظهر تلقائياً بدون تعديل كود الأمر.

#### 📣 الإعلان التلقائي عن بثوث الستريمرز (`/اضافة ستريمر` · `/ازالة ستريمر`)

للمالك فقط (`OWNER_DISCORD_ID`، والتحقق داخل الكود). تسجّل ستريمر (يوزر + منصة TikTok/Twitch/YouTube/Kick) مرة وحدة، وبعدها كل ما **يربط بثه بأحسمها** ينتشر برووم الإعلانات `1552252935377780777` (`STREAM_ANNOUNCE_CHANNEL_ID`): **"حياكم ستريمر يبث احسمها @everyone"** + Embed برابط البث وزر "شاهد البث الآن".

- **المحرّك:** `services/streamerAnnouncer.js` يشترك بـ`liveStreams.onChange()` (نفس مصدر `/بث`، بدون Polling جديد)؛ المحفّز ظهور جلسة الحساب (ربط أو لعب) — مستقل عن بدء أي لعبة. المفتاح `platform:normalizedUsername` (مطابقة دقيقة).
- **منع التكرار:** كل ظهور = "حلقة بث" محفوظة بقاعدة البيانات (`streamer_announcement_events`، فهرس فريد جزئي: حلقة مفتوحة واحدة لكل حساب) + حجز ذرّي للإرسال. تغيير لعبة، تحديثات متكررة، Webhook + مزامنة، انقطاع أقل من 3 دقائق، إعادة تشغيل البوت (آخر ظهور خلال 30 دقيقة) ← بدون إعلان جديد. بث جديد بعد انتهاء السابق ← إعلان جديد.
- **الرابط:** يُبنى فقط بعد التحقق من صيغة الحساب لكل منصة (`services/streamLinkResolver.js`)، أو يؤخذ من بيانات الجلسة لو https بنطاق المنصة ولنفس الحساب. ما فيه رابط مؤكد ← ما ينرسل شي.
- **دليل "يبث الآن":** جلسة الموقع نفسها (الربط الناجح بغرفة البث) + تثبيت 8 ثوانٍ. ما فيه تحقق مستقل من المنصات (يحتاج مفاتيح API)، ويمكن توصيله عبر `setLiveVerifier()`.
- **الأعطال:** الروم ناقص الصلاحيات/غير موجود ← تسجيل واضح بدون روم بديل · بدون `Mention Everyone` ← يرسل بدون @everyone ويسجّل المشكلة · فشل مؤكد من ديسكورد ← إعادة محدودة بتباعد · نتيجة غير واضحة (مهلة) ← بدون إعادة · القاعدة معطلة ← ما ينشر ولا يفقد التسجيلات ويعيد المحاولة.

#### 🎮 راوندات الألعاب (`/روليت` · `/دول` · `/قناص`)

الألعاب الثلاث صارت **راوندات ويب مرتبطة بديسكورد** (`services/discordRounds/`): الأمر ينشئ راوند ويرسل **رابطه**، والدخول واللعب والمشاهدة من الرابط (تسجيل دخول ديسكورد). ما فيه زر انضمام بديسكورد، ولا بدء تلقائي — **صاحب الراوند (hostDiscordId) وحده** يبدأ ويطرد ويلغي (من أزرار الرسالة أو من صفحة الراوند، والتحقق دائماً من الخادم).

**التسلسل:**
1. `/دول` (أو `/روليت` / `/قناص`) ← رسالة انتظار **"احسمها | لعبة الدول"** فيها رابط الراوند، المضيف، `اللاعبون 7 / 50`، الحد الأدنى، قائمة المشاركين (تتحدث لحظياً بنفس الرسالة بتجميع ذكي، حتى 50 لاعب ضمن حدود Embed). أزرار الرسالة: رابط الراوند · **بدء الراوند** · **طرد لاعب** · إلغاء (للمضيف فقط).
2. اللاعب يفتح الرابط ← OAuth2 ديسكورد (`identify` فقط، Authorization Code + PKCE + `state`) ← يرجع لنفس الراوند ← البوت يتحقق إنه **عضو بالسيرفر** ← ينضم باسمه وصورته الحقيقيين (الاسم من البوت، ما يقبل اسم من المتصفح).
3. المضيف يضغط **بدء الراوند** (مرة وحدة مهما ضغط) ← عدّاد انتقال قصير ← كل الواجهات المفتوحة تنتقل للعبة تلقائياً. الانضمام ينقفل.
4. تنرسل **رسالة جديدة** "احسمها | الراوند مباشر الآن" (المشاركون، المتبقون، الجولة، صاحب الدور، آخر الأحداث + زر **مشاهدة الراوند مباشرة**) وتتحدث للأحداث.
5. النهاية: الرسالة تتحول إلى **"انتهى الراوند"** (ما تنحذف) + إعلان الفائز **مرة وحدة** (حتى مع إعادة التشغيل)، وتتحرر القناة لراوند جديد.

**اللعب (القرارات كلها من الخادم):**
- **🎯 روليت الإقصاء (دائرة الإقصاء):** الدائرة تدور من وقت بدء موحّد ونتيجة ثابتة من الخادم (كل المتصلين يشوفون نفس القرعة) وتقف على لاعب، وهذا اللاعب **وحده** يختار مين يطرد خلال 15 ثانية (ما اختار ← دوران جديد، و5 مرات ورا بعض ← تنتهي بدون فائز). آخر واحد يفوز.
- **🌍 لعبة الدول:** كل لاعب دولة سرية (ما تنرسل لأحد، حتى صاحبها، ولا تنكشف إلا لحظة إقصائه/فوزه — الخادم يرسل رموز عشوائية للدول الباقية فقط). صاحب الدور يقصي دولة (ولو طلعت دولته أقصى نفسه).
- **🔫 القناص:** قناص عشوائي، والباقين يختبئون بمربع سري من شبكة **1-50 (المربع يتسع لاعبين)** خلال 30 ثانية (اللي ما اختبأ ينطرد). بعدها 4 دقائق صيد: 🔫 سنايبر (مربع، 25 طلقة) · 💣 قنبلة (4 مربعات متجاورة، 6) · ☢️ نيوك (6 متجاورة، 4) — إصابة مربع تقصي كل من فيه. القناص ما يستلم أي مخبأ، والمربعات الفاضية له وحده. صاد الكل ← يفوز القناص · انتهى الوقت ← الناجين يفوزون.

**التصميم:** منسوخ من ملف الموقع (`web/discord-rounds/site-games.css` = قواعد `rd-*` و`s-cell` و`weapon-btn` كما هي): مسرح الراوند، الدائرة وعُقد اللاعبين، منشور القرعة، بطاقات الدول، شبكة القناص، سجل الإصابات، وطبقة الإقصاء المتحركة.

**المشاهدة:** `/discord/watch/<id>` (بدون تسجيل) — نفس أحداث الراوند الحية بوضع القراءة فقط (عرض مبني على أحداث اللعبة نفسها، **مو فيديو مضمّن داخل ديسكورد**: ديسكورد ما يدعم بث حي داخل الرسالة، فالرسالة فيها ملخص + رابط المشاهدة).

**الأمان:** معرّف راوند عشوائي 128 بت · جلسة موقّعة HttpOnly · فحص Origin + هيدر مخصص على كل طلب يغيّر الحالة · حدود معدل · WebSocket بحد اتصالات وحد رسائل · أسرار اللعبة (الدول، المخابئ، مالك كل دولة) ما تطلع للعميل · المطرود ما يرجع لنفس الراوند.

**الاستعادة بعد إعادة التشغيل:** كل راوند يُحفظ بقاعدة البوت (`discord_rounds`، migration 008) والمؤقتات تُستأنف من مواعيد الخادم؛ لو سجل تالف ← يُنهى برسالة بدون فائز.

**الإعداد (متغيرات البيئة):**
| المتغير | الوصف |
|---|---|
| `ROUNDS_PUBLIC_URL` | الرابط العام لخادم البوت (مثال `https://rounds.ehsmaha.com`) — لازم يوصل لـ`PORT` عبر HTTPS/WSS |
| `DISCORD_CLIENT_SECRET` | Client Secret لتطبيق ديسكورد (Developer Portal → OAuth2) — **سر، لا ينحط بالمستودع** |
| `ROUNDS_SESSION_SECRET` | (اختياري) مفتاح توقيع الجلسات؛ وإلا يُشتق من `DISCORD_CLIENT_SECRET` |
| `PORT` | منفذ الخادم العام (مطلوب) |

**إعداد OAuth2 بديسكورد:** Developer Portal → التطبيق → OAuth2 → Redirects ← أضف `ROUNDS_PUBLIC_URL/auth/discord/callback`. بدون `ROUNDS_PUBLIC_URL` و`DISCORD_CLIENT_SECRET` الأوامر الثلاثة ترد برسالة إعداد (ما فيه رجوع للطريقة القديمة).

**الملفات:** `services/discordRounds/` (`roundManager.js` الحالة الوحيدة والصلاحيات · `games/{countries,roulette,sniper,elimination}.js` منطق الألعاب · `roundStore.js` · `presenter.js` رسائل ديسكورد · `auth.js` OAuth · `http.js` الصفحة+REST+WebSocket · `command.js` الأوامر وأزرار المضيف) · `web/discord-rounds/` (الواجهات) · الاختبارات `tests/discordRounds.*.test.js`.

### 🤖 مساعد احسمها الذكي (Gemini)
مساعد دعم ذكي يشتغل بمكانين **بس**: داخل تذاكر الدعم، وعند منشن البوت بأي قناة. يجاوب على أي شي يخص احسمها (الموقع، البوت، الألعاب، الحسابات، الدعم التقني) بالعربي وباختصار، و**يعتذر بأدب عن أي سؤال خارج احسمها**، وما يكشف تعليماته الداخلية حتى لو أحد حاول ("تجاهل التعليمات"...).

**داخل التكتات (`/دعم`):**
1. بعد ما ينفتح التكت (نفس رسالة التكت وزر الإغلاق)، يرسل البوت: **"أهلاً 👋 معك مساعد احسمها، كيف أقدر أخدمك؟"** مع زر **"أريد التحدث مع فريق الدعم"**.
2. أي رسالة يكتبها **صاحب التكت** تروح لـGemini مع **سجل المحادثة كامل لنفس التكت** (يفهم السياق)، والرد بنفس الروم. رسائل الإدارة/رتب الدعم (`/اعداد_رتب_الدعم`) **ما تنرسل** للذكاء الاصطناعي — عشان يقدرون يتدخلون يدوياً.
3. زر **"أريد التحدث مع فريق الدعم"** (لصاحب التكت): يمنشن رتب الدعم ويوقف المساعد بهذا التكت بس (بدون إغلاقه) — والإيقاف ينحفظ حتى بعد إعادة التشغيل.
4. **الإغلاق** (زر "إغلاق التكت" نفسه): **قبل** الأرشفة/الحذف، يطلب البوت من Gemini ملخص: (1) المشكلة، (2) كيف تعامل معها المساعد، (3) انحلت أو احتاجت تدخل بشري — ويرسله لقناة أخبار الأدمن مع: صاحب التكت، سبب الفتح، المدة، ومن أغلقه. لو فشل Gemini: "تعذر توليد ملخص تلقائي" + سجل المحادثة الخام (ملف لو طويل) — **والإغلاق يكمل عادي**. بعدها السجل ينمسح من الذاكرة.
   - حدد القناة بـ`/قناة_اخبار_الادمن قناة:#اخبار-الادمن` (للإدارة). بدونها الإغلاق يشتغل عادي بدون ملخص.

**بالمنشن:** `@احسمها كيف أربط تيك توك؟` بأي قناة عادية ← رد مباشر (Reply) على رسالتك. كل منشن سؤال مستقل (بدون سياق متراكم)، و**سؤال كل 10 ثوانٍ لكل شخص** (أكثر من كذا: "الرجاء الانتظار قليلاً قبل سؤال آخر"). المنشن داخل روم تكت ينعالج بنظام التكت بس (ما يتكرر الرد).

**قاعدة المعرفة — `config/ehsmahaKnowledge.js`:** هذي "ذاكرة" المساعد عن احسمها (تعريف المنصة، أقسام الموقع، الحسابات الرسمية، التسجيل وطريقة اللعب، الأسئلة الشائعة، والتعليمات الصارمة). **أي معلومة مو مكتوبة فيه، المساعد ما يعرفها** — حدّث الأقسام بدون لمس الكود. ألعاب ديسكورد (`config/games.js`) وأوامر `/مساعدة` وأسباب التكتات تنسحب له **تلقائياً**.

**تبديل النموذج:** غيّر `GEMINI_MODEL` بإعدادات Render (مثل `gemini-3.5-flash-lite` الافتراضي، أو `gemini-2.5-pro` أذكى وأبطأ) ← Save ← يعيد التشغيل. ما يحتاج تعديل كود.

- **الاقتراحات:** المساعد يستقبل الاقتراح بنفسه (بدون ما يوجّه لنموذج الموقع) — يشكر العضو ويأكد وصوله، والبوت يرسل الاقتراح **فوراً** لقناة أخبار الأدمن (💡 اقتراح جديد: النص، من، ومكانه)، ويدخل بملخص التكت عند الإغلاق.
- أي خطأ من Gemini (حد الاستخدام، انقطاع، فلاتر الأمان، مهلة) ← رد ودّي: "عذراً، حصل خلل مؤقت، حاول مرة أخرى أو اطلب التحدث مع فريق الدعم".
- الرد الأطول من 2000 حرف ينقسم لعدة رسائل تلقائياً.
- **🎨 يتعلم أسلوبك:** المساعد يتعلم طريقة كلام **مالك السيرفر بس** مع اللاعبين: رسائله داخل التكتات (مع رسالة اللاعب اللي قبلها كسياق) وأي **Reply** يسويه على رسالة لاعب بأي قناة. الأمثلة (آخر 300) تنحفظ بقاعدة بيانات البوت وتنضاف للبرومبت كقسم "أسلوب الرد" — يقلّد النبرة والكلمات والطول والإيموجي، والمعلومات تبقى من قاعدة المعرفة. رسائل باقي الإدارة واللاعبين ما تنحفظ، والمنشنات تنشال، والروابط تصير `[رابط]`، والأوامر والنصوص اللي تشبه توكن/مفتاح ما تنحفظ أبداً. التحكم: `/اسلوب_المساعد` (حالة · تشغيل · إيقاف · مسح، و`المالك:` لتحويل التعلّم لشخص ثاني — لمالك السيرفر فقط).
- **📷 الصور:** المساعد يشوف الصور (png/jpg/webp، حتى 3 بالرسالة، كل وحدة ≤ 5MB، من ديسكورد بس) بالتكت وبالمنشن ويحللها. الصورة تنرسل مع الرسالة الحالية فقط وما تنحفظ بالذاكرة (السجل فيه `[📷 أرفق صورة]`).
- **"كلمتكم بتيك توك/انستقرام":** لو اللاعب قال إنه كلّم حساب احسمها، المساعد يطلب **سكرين شوت للمحادثة**، ولما توصله يحللها: المنصة، يوزر الحساب (يقارنه بـ@ehsmaha7 — لو مختلف ينبّه إنه ممكن انتحال)، التاريخ وأهم اللي انقال — بدون ما يوعد بجوائز أو إجراءات، ولو يحتاج الفريق يوجّهه لزر "أريد التحدث مع فريق الدعم".
- كل تفاعل ينسجل بالسجل (مين سأل، السياق، المدة، نجح أو فشل) **بدون** محتوى الرسائل.
- رسائل التكتات تحتاج **Message Content Intent** (المنشن يشتغل بدونه).

### 🛠️ تحكم المالك باللغة الطبيعية (Owner AI Engine)
تكلّم البوت **بمنشن مباشر** وبكلامك العادي (لهجة سعودية أو فصحى أو إنجليزي) وهو **ينفّذ** فعلاً على ديسكورد — بدون أمر Slash ولا بادئة، ويشتغل تلقائياً مع تشغيل البوت:

> `@احسمها روح روم التحديثات وقل بدأنا فعالية جديدة` ← يرسل الرسالة ويرد: `✅ تم إرسال الرسالة في #التحديثات.`
> `@احسمها سو روم اسمه مسابقات وخله داخل قسم الفعاليات` ← ينشئ الروم داخل القسم
> `@احسمها الحين ارسل فيه إعلان عن مسابقة جديدة وثبت الرسالة` ← يفهم إن "فيه" = الروم اللي أنشأه، ويرسل الإعلان ثم يثبّته

**الهوية:** الحساب `OWNER_DISCORD_ID` فقط (بالمعرّف `message.author.id` — مو الاسم ولا رتبة Administrator ولا ملكية السيرفر، وما يُقبل ادعاء الهوية بالنص). أي حساب ثاني يمنشن البوت يتعامل معه المساعد العادي كالمعتاد. التفويض يُعاد فحصه قبل **كل** خطوة تنفيذ.

**كيف يشتغل:** `intentParser` يرسل طلبك لـGemini الموجود (نفس المفاتيح والتنقل بينها) ويرجع **خطة JSON** من أدوات Discord المسجّلة ← `taskPlanner` يتحقق منها (Schema) ← `entityResolver` يحوّل الأسماء لمعرّفات (يفهم "التحديثات" = `📢┃اخبار-التحديثات` = `updates`، ولو وجد روم متشابهين **يسألك** بدل ما يخمّن) ← `actionExecutor` ينفّذ بـdiscord.js ويتحقق من النتيجة ← تقرير حقيقي. Gemini يخطّط فقط: ما ينفّذ ولا يقرر الصلاحيات، وما فيه `eval` ولا Shell ولا تثبيت حزم — التوسعة بإضافة **أداة** جديدة لـ`services/ownerAI/tools/`.

**الأدوات (48):** رسائل (إرسال/Embed/إعلان/تعديل/تثبيت/حذف رسائل البوت/جلب/رد/صورة من `assets`/ثريدات) · قنوات (نصي/صوتي/قسم/إعلانات، اسم/وصف/نقل/ترتيب، قفل/فتح، صلاحيات، حذف) · رتب (إنشاء/اسم/لون/ترتيب/إسناد/سحب/عرض) · أعضاء (بحث/معلومات/كتم/فك كتم/تحذير/طرد) · قراءة (إحصائيات السيرفر، التكتات المفتوحة، التحذيرات، سجل الإشراف، الألعاب، حالة البوت والمفاتيح).

**خطوات متعددة:** `سو روم X تحت قسم Y واكتب فيه Z وثبتها` تتحول لخطوات مترابطة (`$s1.channelId`)؛ الخطوة التابعة لخطوة فشلت **تنتخطى** والمستقلة تكمل، والتقرير صادق: `أنشأت الروم وأرسلت الرسالة، لكن ما قدرت أثبّت الرسالة لأن صلاحية إدارة الرسائل ناقصة.` الحد 12 خطوة بالطلب.

**التأكيد:** الطلبات الواضحة محدودة التأثير تنفّذ مباشرة. **حذف قناة، طرد، @everyone، تعديل صلاحيات @everyone (قفل/فتح)، رتب إدارية، حذف أكثر من 5 رسائل** ← يعرض ملخص بزري ✅ تأكيد / ✖️ إلغاء (للمالك فقط). الخطة **مجمّدة بمعرّفات الأهداف النهائية + SHA-256** ومحفوظة بقاعدة البيانات: أي تعديل عليها أو تغيير اسم الروم بعد العرض ما يغيّر الهدف، وتنتهي بعد 15 دقيقة، وتنفّذ مرة وحدة، والأزرار تشتغل حتى بعد إعادة التشغيل.

**الحماية:** ما يمنح/يعدّل صلاحيات حساسة (Administrator, ManageRoles…) ولا رتب أعلى من رتبة البوت أو رتب التكامل · يعدّل/يحذف رسائل البوت فقط · الإرسال بـ`allowedMentions` مقفولة (منشن جماعي يحتاج طلباً صريحاً + تأكيد) · الملفات من `assets/` فقط (قائمة بيضاء) · **نص أي رسالة أو اسم روم يقرأه البوت بيانات مو تعليمات**: ما يدخل برومبت Gemini أبداً (يدخله فقط نص رسالتك أنت ومعرّفات) · لا كشف لمفاتيح أو توكنات بأي رد أو سجل.

**الذاكرة:** سياق مؤقت لكل سيرفر (آخر روم/رسالة/رتبة/قسم/عضو) 30 دقيقة، منفصل عن ذاكرة التكتات. **منع التكرار:** نفس الرسالة تنفّذ مرة وحدة (ذاكرة + جدول `owner_ai_tasks`)، والإرسال بـ`nonce` فما يتكرر الإعلان لو انقطعت الشبكة وأُعيدت المحاولة. **السجل:** كل مهمة (طالبها، السيرفر، الأدوات، النتيجة، معرّفات ديسكورد الناتجة) بجدول `owner_ai_tasks`. مهمة انقطعت بإعادة التشغيل تُعلَّم "منقطعة" ويُبلَّغ بالجزء المنفّذ ولا تتكرر تلقائياً.

**قيود Discord/الصلاحيات (وضّحها البوت بدل ما يدّعي):** يحتاج صلاحيات البوت الفعلية لكل عملية (إدارة القنوات/الرتب/الرسائل، كتم الأعضاء، طرد الأعضاء…) وأن تكون رتبته **فوق** الرتب والأعضاء اللي يعدّلهم · روم الإعلانات يحتاج Community مفعّل · البحث عن عضو بالاسم يحتاج Server Members Intent (وإلا استخدم المنشن أو المعرّف) · لا يغيّر حساب المالك ولا صلاحيات نفسه ولا يعرض إعدادات البيئة.

الملفات: `services/ownerAI/` — `ownerGuard` · `ownerMentionHandler` · `intentParser` · `taskPlanner` · `actionExecutor` · `toolRegistry` + `tools/` · `entityResolver` · `conversationMemory` · `executionQueue` · `confirmationManager` · `errorHandler` · `auditLogger`. الاختبارات: `tests/ownerAI.test.js` (Gemini وديسكورد وهميان).

### 🎮 ربط روم ديسكورد بألعاب الموقع
منصة جديدة بنافذة **"ابدأ بثاً سريعاً"** بالموقع، جنب تيك توك وتويتش وكيك ويوتيوب: **💬 ديسكورد**.

1. الستريمر يختار **ديسكورد** ويحط **ID الروم** (كلك يمين على الروم ← Copy Channel ID — أو يلصق رابط الروم) ← "ابدأ الربط". (يقدر يربطه مع تيك توك بنفس الوقت من "أكثر من منصة".)
2. يشغّل أي لعبة ويحط الكلمة المفتاحية مثل العادة.
3. أي أحد يكتب الكلمة المفتاحية بالروم **يدخل اللعبة باسمه وصورته بديسكورد**، وبعدها **يلعب من الروم طبيعي** (أرقام، إجابات، سحب...) — نفس لاعب تيك توك بالضبط، وبكل الألعاب.

**كيف يشتغل:** الموقع يفتح اتصال بث لحظي (Server-Sent Events) على خادم البوت: `GET /api/discord/relay/:channelId`. كل رسالة بالروم توصل الموقع فوراً `{ id, username, displayName, avatarUrl, content }` (الاسم = لقب السيرفر ثم الاسم العام ثم اليوزر، والتشكيل والتطويل ينشالون)، والموقع يمررها للألعاب مثل رسالة شات. **ما فيه Firebase بالمسار أبداً** — صفر حصة Firestore/Realtime Database.

- البوت ما يعالج أي روم إلا وفيه موقع مفتوح عليه، ولو انقطع (تحديث/إعادة تشغيل) الموقع يرجع يتصل لحاله.
- **الرومات الخاصة مرفوضة** (لازم روم عام يشوفه @everyone) — عشان محد يقدر يقرأ روم خاص بمجرد ما يعرف رقمه. `OFFICIAL_GUILD_ID` يحصرها بسيرفر احسمها.
- **حماية السبام تتوقف بالروم وهو مربوط** (اللاعبين يرسلون أرقام وإجابات سريعة ومتكررة) — **حماية الروابط تبقى شغالة**.
- يحتاج **Message Content Intent** مفعّل من Developer Portal.
- اختبار كامل بمتصفح حقيقي (الموقع + خادم البوت + كل الألعاب): `NODE_PATH=$(npm root -g) node tests/e2e/discordRelay.site.e2e.js` (يحتاج Playwright).

### 💬 الردود التلقائية
`/الردود_التلقائية` (للإدارة) يفتح لوحة فيها كل الردود وأزرار:
- **➕ رد مطابق** ← تطلع **نافذة بنص الشاشة** تكتب فيها الكلمة (مثل `السلام عليكم`) ورد البوت (مثل `وعليكم السلام {يوزر} 🌹`). يرد لو الرسالة كاملة هي الكلمة.
- **➕ رد يحتوي** ← نفس النافذة، بس يرد لو الكلمة موجودة داخل أي رسالة (مثل `احسمها`).
- **🗑️ حذف** ← قائمة تختار منها رد أو أكثر تحذفها. **🔄** يحدّث اللوحة.

المطابقة ذكية: التشكيل والتطويل والمسافات وعلامات الترقيم ما تفرق، و`أ/إ/آ = ا`، `ى = ي`، `ة = ه`، والإنجليزي بدون حساسية للحروف الكبيرة.
رد واحد لكل رسالة، ونفس الرد ما يتكرر بنفس القناة خلال 5 ثوانٍ. الرسائل اللي تحذفها الحماية ما ينرد عليها، والبوتات ما ينرد عليها. حد أقصى 100 رد لكل سيرفر.
`{يوزر}` بالرد = منشن للعضو · `{السيرفر}` = اسم السيرفر. يحتاج **Message Content Intent**.

### كيف تنحسب الأرقام (من بيانات الموقع الفعلية)
- **اللفل/XP/الجولات:** من `levels/{key}` بنفس معادلة الموقع بالضبط (`30 × level^1.5`). لو اللاعب رابط تيك توك، له سجلان (يوزر الموقع + تيك توك): اللفل/XP = الأعلى (مثل الموقع)، والجولات وعدّاد الألعاب = **مجموع** الاثنين (كل جولة تنحسب لسجل واحد فقط)، والإطارات = اتحادهم.
- **الإطارات:** `ownedFrames` من السجلين (Firestore + RTDB)، أسماؤها من كتالوج الموقع و`framesCatalogExtra`، والمفعّل = الأحدث تفعيلاً.
- **الإنجازات:** نفس قائمة الموقع (14 وسام) وبنفس الشروط.
- **أكثر ستريمر يلعب عنده:** الستريمر اللي فاز اللاعب عنده أكثر شي بقوائم `leaderboards` (بمعرّف تيك توك المربوط).
- **النقاط:** `users.onlinePoints` (لاعب البث بدون حساب بالموقع: النقاط والفوزات الفردية/الأونلاين = 0 لأنها خاصة بالحسابات).
- **الانتصارات:** فوزات فردي (`soloWinCount`) + أونلاين (`onlineWinCount`) + فوزات البث بكل قوائم الستريمرز (`leaderboards`).
- **الهزائم:** الموقع ما يسجّل خسارة صريحة، فكل جولة لعبها بدون فوز = هزيمة (`الجولات − الانتصارات`). لو الفوزات أكثر من الجولات المسجّلة (فوزات قديمة قبل نظام الجولات) تظهر الهزائم ومعدل الفوز "—" بدل رقم غلط.
- **الترتيب العام:** ترتيب اللاعب بالـXP بين كل لاعبي `levels`.
- **المتصدرين الأسبوعي:** الموقع ما يخزن XP أسبوعي، فالـAPI ياخذ **لقطة XP** لكل اللاعبين مع بداية كل أسبوع (الأحد 00:00 بتوقيت السعودية) ويحسب الفرق. أول أسبوع بعد النشر يبدأ من لحظة التشغيل ويوضّح ذلك بالرسالة.
- **أعلى نقاط بجولة:** يبدأ التسجيل من تاريخ نشر تعديل الموقع (ما فيه بيانات تاريخية له).

## 📡 Webhook البث — للفريق التقني بالموقع

`/بث` يشتغل **بدون أي تعديل على الموقع** وبنفس مصدر قائمة "ستريمرز يبثون الآن" بلوحة المالك (`ownerRenderStreamers`) ونفس قواعد دمجها:
- **RTDB `fsMirror/activeStreamers/link_<uid>`**: يكتبه الموقع **لحظة نجاح ربط اليوزر** (قبل أي لعبة) ويتحدّث باسم اللعبة، ويحذفه تلقائياً (`onDisconnect`) لما تنقفل الصفحة أو ينفك الربط. الأقدم من 12 ساعة يتجاهل.
- **Firestore `activeStreamers/{gameTag}`** (لعبة شغّالة) + **`presence`**: يظهر فقط الحاضرون فعلاً (نبضة خلال آخر 3 دقائق).
- الدمج: ستريمر واحد لكل (منصة + يوزر)؛ اللي عنده لعبة يغلب، وإلا الأحدث. بدون لعبة = "📡 متصل بالبث".

**اللحظية:** مع الـAPI المدمجة (الافتراضي) البوت يستمع مباشرة لـFirestore وRTDB (`onSnapshot` / `on('value')`)، فأي ربط/لعبة/انقطاع يوصل `/بث` خلال أجزاء من الثانية وتتعدّل **رسالة `/بث` المفتوحة نفسها** (14 دقيقة من آخر ضغطة؛ كل ضغطة زر تجدّد النافذة). مع API منفصلة (`API_BASE_URL`) ما فيه دفع لحظي، فالمزامنة دورية (`STREAM_POLL_SECONDS`).
الـWebhook **اختياري** وما عاد يحتاجه الظهور اللحظي.

**العنوان:** `POST https://<خدمة-البوت>.onrender.com/api/discord/stream-event`
**الهيدرز:** `Content-Type: application/json` و `x-webhook-secret: <STREAM_WEBHOOK_SECRET>`

بداية بث / تغيير اللعبة:
```json
{
  "sessionId": "bomb:uid123",
  "platform": "tiktok",
  "platformUsername": "streamer_name",
  "gameName": "القنبلة المتحركة",
  "gameId": "bomb",
  "startedAt": "2026-09-23T18:00:00Z"
}
```
نهاية البث:
```json
{ "sessionId": "bomb:uid123", "ended": true }
```

| الحقل | الشرط |
|---|---|
| `sessionId` | 1–128 حرف: `A-Z a-z 0-9 : _ . -` — نفس القيمة بالبداية والنهاية |
| `platform` | `tiktok` / `twitch` / `kick` / `youtube` |
| `platformUsername` | حتى 64 حرف (الـ`@` بالبداية ينشال تلقائياً) |
| `gameName` | حتى 100 حرف |
| `gameId` | اختياري |
| `startedAt` | اختياري — ISO أو مللي ثانية (الافتراضي: وقت الاستلام) |

**الردود:** `200` نجاح · `400` حمولة غلط (الرسالة توضح الحقل) · `401` سر غلط · `422` جلسة أقدم من 6 ساعات · `429` طلبات كثيرة (120/دقيقة) · `503` السر مو مضبوط بالبوت.

**مثال (curl):**
```bash
curl -X POST https://ehsmaha-discord-bot.onrender.com/api/discord/stream-event \
  -H "Content-Type: application/json" -H "x-webhook-secret: $STREAM_WEBHOOK_SECRET" \
  -d '{"sessionId":"bomb:uid123","platform":"tiktok","platformUsername":"streamer_name","gameName":"القنبلة المتحركة","gameId":"bomb"}'
```

**الضمانات:**
- ستريمر واحد = جلسة وحدة (جلسة جديدة لنفس الستريمر تستبدل القديمة).
- لو ما وصل حدث النهاية أبداً (المتصفح انهار): الجلسة تنحذف تلقائياً بعد 6 ساعات، وغالباً قبلها بكثير بالمزامنة (أول ما يختفي حضوره من الموقع).
- لو فشل الـWebhook: المزامنة تعوّضه خلال دقيقة. ولو فشلت المزامنة: الحالة الحالية تبقى لين تنجح.

> 🔐 **أمان:** السر **لا يوضع أبداً** بكود المتصفح (`index.html`) — أي زائر يقدر يقراه ويزوّر جلسات. أرسل الأحداث من سيرفر (مثل Firebase Cloud Function على `onWrite` لـ`activeStreamers/{gameTag}`). وحتى لو انسرّب السر، المزامنة تحذف أي جلسة مزوّرة ما لها وجود ببيانات الموقع خلال دقيقة.

## ➕ إضافة أمر جديد

1. أنشئ ملف داخل `commands/` (بأي مجلد فرعي)، مثلاً `commands/fun/ping.js`:

```js
'use strict';
const { SlashCommandBuilder } = require('discord.js');
const eb = require('../../utils/embedBuilder');
const respond = require('../../utils/respond');

module.exports = {
  data: new SlashCommandBuilder().setName('بينق').setDescription('يختبر سرعة استجابة البوت'),
  async execute(interaction) {
    const embed = eb.brand({ title: '🏓 بونق!', description: `${interaction.client.ws.ping}ms` });
    return respond.send(interaction, { embeds: [embed] });
  },
  // اختياري: معالجات أزرار حسب بادئة customId ("ping:...")
  // buttons: { ping: async (interaction, args) => { ... } }
};
```

2. `npm run check` للتأكد من الاسم والوصف.
3. `npm run deploy-commands:guild` للتجربة، ثم `npm run deploy-commands` للنشر.

**قواعد:** كل رد عبر `respond.send` (يتعامل مع defer/reply تلقائياً)، كل Embed عبر `embedBuilder` (الهوية الموحدة)، وكل طلب بيانات عبر `apiClient`. الأخطاء غير المتوقعة يلتقطها الموزّع المركزي ويرد برسالة ودّية.

أمر يحتاج يوزرنيم؟ استخدم `addUsernameOption` و`readUsername` و`notFoundPayload` و`autocompleteUsernames` من `utils/player.js` (نفس ما يستخدمه `/بروفايل`).

لإضافة مسار API جديد: دالة بـ`api/services/` + مسار بـ`api/routes/discord.js` + دالة بـ`utils/apiClient.js`.

## 🛡️ الموثوقية والأمان
- `try/catch` حول كل تفاعل وكل معالج حدث؛ `unhandledRejection` / `uncaughtException` تُسجَّل بدون إيقاف العملية.
- رسائل الخطأ للمستخدم عامة وودّية فقط — التفاصيل التقنية بالسجل.
- السجلات (winston) تحجب تلقائياً التوكنات والمفاتيح وأي `Authorization`.
- Rate limit: أمر كل 3 ثوانٍ لكل مستخدم (البوت) + حد طلبات بالـAPI.
- كاش: المتصدرين (البوت 90ث، الـAPI 120ث)، الاقتراحات والفعاليات 60ث، فوزات البث 10د — مع منع الطلبات المتزامنة المكررة.
- إعادة الاتصال بـDiscord تلقائية، وكل مراحلها (disconnect/reconnecting/resume) مسجّلة.
- مقارنة `x-api-key` ثابتة الزمن؛ helmet؛ الـAPI للقراءة فقط على بيانات الموقع.

## 🔧 حل المشاكل
| المشكلة | الحل |
|---|---|
| الأوامر ما تظهر | `npm run deploy-commands` — وتأكد إن رابط الدعوة فيه `applications.commands` |
| الأوامر تظهر مرتين | سجّلتها عالمياً وبسيرفر التطوير: `npm run clear-commands:guild` |
| كل الأوامر ترد "حصل خطأ مؤقت" | الـAPI طايح أو `API_KEY` مختلف بين الخدمتين — راجع سجلات خدمة الـAPI و `/health` |
| "تأكد من DISCORD_TOKEN" بالسجل | التوكن غلط أو انعمل له Reset |
| "لم يتم العثور على لاعب" ليوزر موجود | اكتبه كما هو بالموقع (بدون الاسم الظاهر/النيكنيم) أو اختره من الاقتراحات |
| "البوت يجهّز بياناته" بالأوامر الإدارية | البوت يسترجع قاعدته بعد التحديث (دقيقة غالباً — لو خدمة الـAPI نايمة تاخذ أطول). لو طوّل: تأكد إن خدمة الـAPI شغالة ومحدّثة |
| الترحيب ما يشتغل | `/تجربة_الترحيب` يقولك وين المشكلة؛ فعّل **Server Members Intent**، وأعطِ البوت **Attach Files** بالقناة |
| الروابط ما تنحذف | فعّل **Message Content Intent**، وتأكد من `/حالة_الحماية` (صلاحيات ناقصة؟ القناة/الرتبة مستثناة؟) |
| البوت ما يكتم عضو | رتبة العضو أعلى من رتبة البوت — اسحب رتبة **احسمها** فوقها |
| "رتبة العضو أعلى من رتبة البوت" | اسحب رتبة **احسمها** فوق رتب الأعضاء ورتب التحذير |
| البوت يقول "ناقصني صلاحية …" | أعطِ رتبة البوت الصلاحية المذكورة، أو ادعه من جديد بالرابط أعلاه |
| `/بث` فاضي والستريمر يبث | يظهر خلال دقيقة (المزامنة) — تأكد إن صفحة اللعبة مفتوحة عند الستريمر؛ للظهور اللحظي فعّل الـWebhook |
| الـWebhook يرجّع 503 | `STREAM_WEBHOOK_SECRET` مو مضبوط بخدمة البوت |
| `/عرض_الرتب` يعرض "—" بدل العدد | فعّل **Server Members Intent** بـDeveloper Portal → Bot |
| البوت يصير أوفلاين فجأة بدون سبب واضح | الخطة المجانية بـRender تنيّم الخدمة — البوت يصحّي نفسه كل 10 دقائق تلقائياً، لضمان 24/7 كامل رقّي لخطة Starter المدفوعة |
| أوامر /ربط و/فك_ربط القديمة ظاهرة | شغّل `npm run deploy-commands` من جديد — التسجيل يستبدل القائمة ويحذفها |
