# الأراضي البركانية 🌋

وضع لعب جديد داخل موقع **ehsmaha.com**. كل مشارك يقف فوق عمود من البلوكات في كهف
بركاني، يظهر سؤال في منتصف الشاشة مع 4 خيارات، ويجاوب المشاهد بكتابة `1` أو `2` أو
`3` أو `4` في شات البث. الإجابة الصحيحة والسريعة تضيف بلوكات تحت قدميه فيرتفع. في
نهاية كل جولة تصعد اللافا، ومن وصلت لسطح برجه احترق وخرج. آخر ناجٍ = الفائز.

---

## البنية

الموقع ملف `index.html` واحد بلا خطوة بناء. لذلك المنطق مكتوب بـTypeScript صارم في
مجلد مستقل ويُبنى لملف JS واحد يُحقن داخل `index.html` بين علامات ثابتة — فيبقى نموذج
النشر (ملف واحد مستقل) كما هو تماماً.

```
games/volcanic-lands/
├── data/questions.ar.json      بنك الأسئلة — 500 سؤال كما استُلم، بلا أي تعديل
├── src/                        المنطق الخالص (صفر DOM)
│   ├── config.ts               كل رقم في اللعبة — لا رقم سحري خارجه
│   ├── types.ts                الأنواع
│   ├── state-machine.ts        آلة الحالة الصريحة + ملكية المؤقّتات
│   ├── question-bank.ts        الاختيار العشوائي ومنع التكرار
│   ├── scoring.ts              الطبقات الزمنية واللافا والترتيب والتعادل
│   ├── normalize.ts            تطبيع الشات ومطابقة الإجابات
│   ├── storage.ts / random.ts  تخزين وعشوائية قابلان للحقن (للاختبار)
│   └── engine.ts               المحرّك الذي يربطها
├── ui/                         طبقة الواجهة (JS خام بنمط الموقع)
│   ├── volcanic-lands.css      الأنماط — مطابقة للتصميم المرفق
│   ├── volcanic-lands.pages.html  صفحتا الإعداد ولوحة الستريمر
│   └── volcanic-lands.ui.js    الربط بالـDOM وبشات البث
├── test/                       اختبارات vitest
├── e2e/smoke.mjs               اختبار متصفح حقيقي (Playwright)
└── scripts/build.mjs · inject.mjs
```

## التشغيل

```bash
npm install
npm run typecheck     # TypeScript صارم — صفر أخطاء
npm test              # اختبارات الوحدة والمحاكاة
npm run sim           # يطبع إحصائية 1000 مباراة
npm run build         # يبني dist/volcanic-lands.logic.js
npm run inject        # يحقن كل الكتل داخل ../../index.html
npm run e2e           # مباراة كاملة في متصفح حقيقي + لقطات شاشة
```

`inject` يعمل بعلامات `<!-- BEGIN/END volcanic-lands:* -->`، فتشغيله مرات متتالية
لا يضاعف شيئاً، ولا يلمس أي كود قائم في الموقع — خمس كتل: `style`, `pages`, `card`,
`logic`, `ui`.

## القواعد

كل الأرقام في `src/config.ts`:

| البند | القيمة |
|---|---|
| مدة السؤال | 20 ثانية (يضبطها الستريمر 10–60) |
| ارتفاع البداية | 5 بلوكات |
| ≤ 10 ثوانٍ | 10 نقاط · 4 بلوكات |
| ≤ 15 ثانية | 8 نقاط · 3 بلوكات |
| أبطأ | 5 نقاط · 2 بلوك |
| خطأ | 0 · 0 |
| صعود اللافا | `r + 1` → 2، 3، 4، 5، 6 … |
| أقصى جولات | 12، بعدها مرحلة حسم مضاعفة |
| أقصى لاعبين | 60 |

**لماذا خطّي لا مضاعف؟** بالتصاعد المضاعف (2، 4، 6، 8) تتجاوز اللافا أسرع لاعب
ممكن في الجولة الثالثة فيحترق الجميع دفعة واحدة. الصيغة الخطية تعطي 5–8 جولات
(محقّقة بالمحاكاة: متوسط 5.74).

الصعوبة (سهل/عادي/جحيم) تغيّر **سرعة صعود اللافا فقط**، لا صعوبة الأسئلة —
صعوبة الأسئلة مربوطة برقم الجولة: 1‑2 → صعوبة 1، 3‑4 → صعوبة 2، 5+ → صعوبة 3.

## مخطّط بنك الأسئلة

`data/questions.ar.json` يُستورد **كما هو حرفياً** ولا يُعدَّل. حقوله:

```json
{ "total_questions": 500,
  "questions": [{ "id": 1, "question": "...", "options": ["أ","ب","ج","د"],
                  "correct_answer": "ب", "correct_index": 1,
                  "difficulty": "easy|medium|hard", "category": "ديني" }] }
```

التطبيع يحدث في `presentQuestion()` فقط: المعرّف الرقمي يصير نصّاً،
و`question → text`، و`correct_index → correctIndex` (بعد الخلط)،
و`correct_answer → answer`، و`easy/medium/hard → 1/2/3` لتصاعد الجولات.
الفئات التسع تُعرض كما هي على شارة الكرت.

| الصعوبة | العدد |  | الفئات |
|---|---|---|---|
| easy | 211 |  | ديني 84 · جغرافيا 79 · لغة عربية 70 |
| medium | 211 |  | تاريخ 60 · ثقافة عامة 59 · رياضة 49 |
| hard | 78 |  | السعودية 39 · شخصيات 30 · عملات ودول 30 |

## منع تكرار الأسئلة

`sessionId` يُنشأ ويُخزَّن **مرتبطاً بحساب الستريمر** لا بجولة اللعب الواحدة. السؤال
يُعلَّم مستخدَماً **بمجرد عرضه** (لا بعد الإجابة) ويُحفظ فوراً، فيصمد أمام إعادة
تحميل الصفحة وانقطاع الاتصال.

- إيقاف الجولة والرجوع، أو `إعادة تشغيل` → **نفس الجلسة**، لا يتكرر أي سؤال سبق عرضه.
- زر **`🆕 جلسة جديدة`** هو الوحيد الذي يصفّر `usedQuestionIds` وينشئ `sessionId` جديداً.
- الاختيار عشوائي دائماً (Fisher–Yates بمولّد جديد كل مرة)، لا بترتيب الملف.
- عند نفاد صعوبة معيّنة يُسحب من الأقرب بدل التكرار.
- إعادة التدوير مسموحة **فقط** بعد استهلاك البنك كاملاً (500 سؤال).

## شات البث

اللعبة تُسجَّل في ناقل الأحداث المركزي الموجود أصلاً في الموقع — **بلا أي اتصال
WebSocket جديد**:

```js
homeRegisterGameListener('volcanic-lands', vlHandleEvent);
```

- مطابقة **تامة** بعد التشذيب: «أعتقد 3» لا تُحتسب.
- يقبل `1 ٢ 3 ٤` و`a b c d` و`أ ب ج د`، ويزيل الحركات والإيموجي والمحارف غير المرئية.
- إجابة واحدة لكل لاعب لكل جولة — الأولى فقط، لا تراجع.
- إزالة التكرار حسب `userId` لا حسب الاسم.
- تجاهل ما يزيد على 5 رسائل من نفس المستخدم في الثانية.
- الأحداث تدخل **طابوراً** يُفرَّغ مرة كل إطار — لا معالجة داخل حلقة الرسم.
- الزمن يُقاس من لحظة **عرض** السؤال، مع خصم تأخير الشات إن كان في الحدث.
- لا تُكشف إجابة أي لاعب قبل `REVEAL` — فقط علامة «أجاب» وعدّاد «أجاب N لاعب».

## الإنعاش بهدايا تيك توك

مفتاح اختياري في «خيارات إضافية». عند تفعيله، أي مشاهد يرسل هدية يعود لاعبه
المحترق فوق سطح اللافا الحالي بـ2 بلوك — فلا يغرق فوراً في نفس الجولة.

- تصل الهدايا عبر **نفس ناقل الأحداث** الذي يصل منه الشات (`WebcastGiftMessage`)
  — بلا أي اتصال جديد.
- الحد الأدنى للهدية وعدد مرات الإنعاش لكل لاعب في `src/config.ts` (`revive`).
- المحرّك وحده يقرر القبول أو الرفض: مطفأ · اللاعب حيّ · هدية صغيرة ·
  تجاوز الحد · انتهت المباراة. الواجهة تعرض النتيجة فقط.
- زر **«🎁 محاكاة هدية»** يجرّب المسار كاملاً قبل البث.

## المقاسات التلقائية والصفوف

المقاسات تُحسب كل إطار من **العرض والارتفاع الفعليين للساحة معاً**:

- **العرض** يحدّد عرض البرج والفجوة.
- **الارتفاع** يحدّد ارتفاع البلوك: يُحسب أطول بلوك ممكن دون أن يخرج أطول برج
  عن الساحة. لذلك تكون البلوكات ضخمة في الجولات الأولى وتقصر تدريجياً كلما
  ارتفعت الأبراج — بدل ترك ٨٠٪ من الساحة فارغة كما كان.
- **الصفوف**: إذا ضاق عرض البرج عن الحد المقروء (54px) يُوزَّع اللاعبون على
  صفّين أو ثلاثة **بعمق مختلف** (الخلفي أعلى وأصغر وأخفت) — فتتضاعف المساحة
  لكل لاعب بدل أن ينكمش الجميع لشرائط. قمم الأبراج الخلفية تبقى أعلى من
  الأمامية دائماً لأن قاعدتها أعلى، فلا تحجبها.

| الحالة | صفوف | عرض البرج | الأفتار |
|---|---|---|---|
| مكتب · 20 لاعباً | 1 | 58px | 55px |
| مكتب · 60 لاعباً | 3 | 58px | 55px |
| جوال · 20 لاعباً | 3 | 38px | 36px |

إغلاق شات البث يوسّع الساحة فتكبر الأبراج في الإطار التالي تلقائياً.

## انحرافات مقصودة عن المواصفة

1. **الرندر DOM/CSS ‏2D بدل Three.js.** المواصفة طلبت Three.js *و* مطابقة التصميم
   المرفق — والتصميم المرفق نفسه ‎DOM/CSS مسطّح تماماً (بلوكات `div`، لافا `gradient`،
   بلا كاميرا). التعليمتان متناقضتان، والمطابقة هي المُختارة (بقرار صريح منك).
   نتيجةً لذلك «وضع 2D الاحتياطي» تحوّل إلى **وضع مؤثرات منخفضة** (`vl-lowfx`)
   يُفعَّل تلقائياً إذا نزلت الإطارات تحت 30 لمدة 5 ثوانٍ.

2. **لا نقطة `/api/avatar` جديدة.** الموقع يحلّ مشكلة CORS أصلاً عبر
   `avatarProxyUrl()` (وسيط `images.weserv.nl`) مع سلسلة بدائل من مرحلتين
   يستخدمها كل الألعاب. بناء وسيط ثانٍ كان سيُكرّر بنية قائمة ويُحمّل سيرفر
   الجسر بلا داعٍ. أعدنا استخدام الموجود وأضفنا فوقه **طبقة الكاش المفقودة**
   (ذاكرة + `localStorage` حسب `userId`) التي طلبتها المواصفة فعلاً.

3. **لا لوحة «أفضل 5» جانبية.** كانت تكرّر أرقاماً يعرضها الشريط العلوي داخل
   الساحة أصلاً، وتخنق الملعب على الجوال. الترتيب الكامل يظهر في شاشة التتويج.

4. **صفحتان بدل تبويب.** المواصفة قالت «تبويب جديد في لوحة التحكم»؛ الموقع لا
   يملك لوحة تحكم بتبويبات — نمطه صفحة إعداد + صفحة لوحة ستريمر لكل لعبة، وهو
   ما اتُّبع.

5. **أرقام لاتينية.** التصميم المرفق يستخدم أرقاماً عربية-هندية، لكن الموقع
   يستخدم اللاتينية في كل نص وظيفي (89 محرفاً عربياً-هندياً في الملف كله، كلها
   زخرفية). المواصفة نصّت على اتّباع الموقع.

6. **الاسم.** كل نص مرئي يقول **«الأراضي البركانية»**؛ لم تُستخدم «أراضي اللافا»
   ولا «طوفان اللافا» في أي مكان يراه المستخدم، رغم ورودهما في الملفين المرفقين.
