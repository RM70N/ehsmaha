# احسمها | تطبيق سطح المكتب لويندوز (Electron)

تطبيق ويندوز مستقل لمنصة [ehsmaha.com](https://ehsmaha.com): نافذة خاصة، أيقونة، قائمة ابدأ، شريط النظام،
إشعارات ويندوز، وتحديث تلقائي للتطبيق ولمحتوى الموقع. نفس Firebase ونفس جسور البث، **بدون أي تعديل على
منطق الموقع أو الألعاب أو قاعدة البيانات**.

- تقرير الفحص والمعمارية: [`AUDIT.md`](./AUDIT.md)
- تقرير الاختبارات الصادق (ما اختُبر وما لم يُختبر): [`TEST-REPORT.md`](./TEST-REPORT.md)

## كيف يعمل

1. **نسخة كاملة من الموقع داخل التطبيق** (`desktop/site/`، 67 ملفاً: `index.html` + 12 صفحة لعبة + السكربتات والمجلدات
   التي ينشرها `pages.yml`) تُخدَم من سيرفر محلي `http://localhost:43711` (أصل ثابت ⇒ جلسة Firebase تبقى محفوظة،
   وFirebase يرفض `file://`). التطبيق يعمل حتى لو بطؤ الموقع الحيّ.
2. **مزامنة المحتوى بـManifest** (`content-manifest.json` المنشور مع الموقع): كل ملف بحجمه وSHA-256 وإصدار موحّد.
   التطبيق يجلب المتغيّر فقط إلى `staging`، يتحقق من البصمات ومن التبعيات (كل `<script src>` / `<link href>` / `<iframe>`
   مطلق موجود)، ثم ينقل الإصدار ذرياً إلى `versions/<الإصدار>/`. لا يُنفَّذ أي كود Node من المحتوى المنزَّل.
3. **لا قطع للجولات.** الإصدار الجاهز يُطبَّق فقط عند «نقطة آمنة» (صفحة خاملة، لا بث متصل، لا لعبة نشطة، لا مستمعو
   ألعاب). أثناء الجولة يظهر مرة واحدة: «وصل تحديث جديد لأحسمها، بيصير جاهز بعد الجولة» مع زر «طبّق الآن»
   (موافقة صريحة)، ويُطبَّق تلقائياً عند أول عودة للخمول. فحص صحة بعد التطبيق، وفشله ⇒ **تراجع تلقائي** للإصدار
   السابق وحظر الإصدار المعيب.
4. **تحديث التطبيق نفسه** عبر `electron-updater` + GitHub Releases: تنزيل بالخلفية، التثبيت عند إغلاق التطبيق أو من
   الإعدادات (مع تحذير إن كانت هناك جولة)، لا خفض لإصدار أقدم.
5. **تسجيل الدخول بجوجل عبر متصفح النظام** (جوجل تحجب المتصفحات المدمجة): التطبيق يفتح
   `https://ehsmaha.com/desktop-auth.html?port=…&state=…` ← تسجيل الدخول ← إرجاع بـPOST إلى
   `http://127.0.0.1:PORT/__auth/callback` (state عشوائي أحادي الاستخدام ٥ دقائق، فحص الأصل والمنفذ) ←
   `signInWithCredential` داخل صفحة الموقع. التوكنات لا تظهر في رابط أو لوغ.
6. **إشعارات ويندوز** من مصادر موثوقة فقط (مستندات لا يكتبها إلا المالك حسب `firestore.rules`):
   `broadcastMessages/current`، `personalMessages/{user}` (للمستلم)، `storeNewAnnouncements/current`،
   `streamerEventAnnouncements/current`، + «لعبة جديدة» من فرق الـManifest + تحديثات التطبيق.
   منع تكرار، حد معدل (٥/دقيقة)، تجاهل القديم (>١٠ دقائق)، لا إشعار نظام والنافذة أمامك، نص عام للرسائل
   الخاصة على شاشة القفل، النقر يفتح النافذة (وينقل لوجهة آمنة من قائمة بيضاء فقط إن لم تكن هناك جولة).

## ما الذي لا يفعله (بصدق)

- **لا إشعارات والتطبيق مغلق تماماً** (خروج كامل من الـTray): لا يوجد Push Service (WNS/FCM) مُعدّ. الإشعارات
  تعمل أثناء: النافذة مفتوحة غير مركّزة، مصغّرة، أو مخفية في الـTray (العملية حيّة). هذا مقصود ومُوثَّق.
- **Focus Assist / عدم الإزعاج**: ويندوز نفسه يؤجّل أو يكتم الإشعارات؛ التطبيق لا يتجاوزه.
- **التوقيع الرقمي**: غير مفعّل لعدم وجود شهادة؛ ويندوز SmartScreen قد يحذّر عند أول تثبيت. يُفعَّل تلقائياً عند
  ضبط أسرار `CSC_LINK` و`CSC_KEY_PASSWORD` في GitHub.

## التشغيل المحلي (تطوير)

```bash
cd desktop
npm ci
npm start            # يجمّع الموقع + الأيقونات ثم يشغّل التطبيق
npm run start:remote # يحمّل الموقع الحيّ مباشرة (للمقارنة فقط)
npm run lint && npm test
xvfb-run -a npm run test:e2e   # اختبارات Electron الحقيقية (لينكس: Xvfb)
```

`desktop/site/` ناتج بناء مُتجاهَل في git؛ يُعاد توليده من جذر المستودع بقائمة ملفات واحدة
(`scripts/site-files.js`) يتحقق اختبار تلقائي من تطابقها مع `pages.yml`.

## البناء والإصدار

- البناء الحقيقي لـ`ehsmaha-setup.exe` يتم على `windows-latest` عبر
  [`.github/workflows/desktop-release.yml`](../.github/workflows/desktop-release.yml) عند رفع تاج `vX.Y.Z`
  يطابق `desktop/package.json`.
- مراحل الـworkflow: التحقق (تطابق التاج + `npm audit` + lint + اختبارات الوحدة + E2E) ← بناء NSIS ← التحقق من
  المخرجات (`ehsmaha-setup.exe` + `.blockmap` + `latest.yml`، تطابق sha512 والإصدار) ← النشر. **لا يُحذف ولا
  يُستبدل أي أصل منشور لنفس الإصدار**؛ كل إصدار برقم جديد.
- نشر الموقع (`pages.yml`) مستقل تماماً: تعديل الموقع لا يتطلب إصدار EXE جديد.

```bash
# إصدار جديد
# 1) ارفع الرقم في desktop/package.json  2) commit
git tag v1.1.0 && git push origin v1.1.0
```

رابط التحميل الثابت (يستخدمه زر الموقع): `https://github.com/rm70n/ehsmaha/releases/latest/download/ehsmaha-setup.exe`

## الإعدادات داخل التطبيق

قائمة «التطبيق ← الإعدادات» أو أيقونة الـTray: إصدار التطبيق والمحتوى، فحص التحديث، إعادة تحميل المحتوى،
تشغيل مع ويندوز (**معطّل افتراضياً**)، الإغلاق إلى الـTray، تفعيل/تعطيل الإشعارات حسب النوع + الصوت + إشعار
تجريبي، حجم الواجهة، ملء الشاشة (F11)، نسخ بيانات التشخيص، فتح مجلد السجلات.

## الأمان

`contextIsolation` + `sandbox` + `nodeIntegration:false` + `webSecurity` (لا تُعطَّل أبداً؛ `npm run lint` يفشل إن ظهر
ذلك) • preload صغير بلا `require` محلي • IPC بقائمة قنوات مع فحص هوية المرسل (إطار التطبيق الرئيسي / صفحة
الإعدادات فقط) والتحقق من كل مُدخل • أذونات محصورة بأصل التطبيق • الروابط الخارجية بالمتصفح (http/https/mailto فقط،
بلا بيانات اعتماد) • CSP صريحة • لا أسرار داخل التطبيق • سجلات محلية فقط مع حجب كلمات المرور والتوكنات
ومفاتيح API، لا إرسال خارجي • أدوات المطوّر مغلقة في الإنتاج.
